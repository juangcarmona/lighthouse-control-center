# Tests

`tests/product-behaviours/bindings.json` connects nine draft ProductShape Given/When/Then examples to their existing requirement digests and concrete Playwright cases. Node checks reject changed product sources, duplicate identities and missing case declarations. The browser reporter writes `structured-behaviours.json` and ProductShape-format verification evidence under a timestamped `test-results/product-behaviours/` directory. Fixture-backed browser results are integration evidence; they do not confirm a GitHub user effect or accept the draft Product Change. Each example retains its conjunctive outcomes and limitations.

`npm run test:e2e:live` is a separate real-service suite, outside PR/push CI. It requires explicit `LCC_E2E_ORIGIN` (HTTPS), `LCC_E2E_REPOSITORY`, `LCC_E2E_ISSUE`, `LCC_E2E_USER` and `LCC_E2E_REALM_FILE` for the configured development Keycloak test account. Set `NODE_EXTRA_CA_CERTS` to the development CA for Playwright's Node HTTP client and, when needed, `LCC_E2E_BROWSER_HOME` to the existing isolated browser trust profile. It creates a fresh provider session and uses the application's retained, independently verified GitHub connection; it accepts no GitHub token or operator CLI fallback. It checks repository navigation, exact issue lookup, conversation, source-action restrictions and anonymous denial. Source tests must run against an explicitly selected configured repository/ordinary issue.

Ordinary-comment publication additionally requires `LCC_E2E_ALLOW_COMMENT=true`. That case leaves one real comment on the selected issue, confirms its source receipt, and never retries an uncertain send. Without opt-in it is inconclusive, not a successful publication test. Traces, video and automatic screenshots are disabled for live runs; explicit screenshots are taken only after authentication. Results are under `test-results/e2e/` and `test-results/product-behaviours-live/`. ProductShape's evidence command requires a v1alpha2 configuration; the current v1alpha1 adoption is unchanged. For this increment its report was checked with the installed CLI against a disposable v1alpha2 view containing byte-identical baseline artifacts, rather than silently migrating the repository format.

If a publication response is lost, run the recovery case with the exact `LCC_E2E_RECOVER_COMMENT_ID` returned by GitHub. It recovers or reconciles the existing journal entry, verifies that source comment in the conversation, and asserts that no prepare or submit request occurred. It never creates a replacement comment. The publishing case waits for current comment authority before entering text; receipt waits allow the bounded server operation to finish. Failed publication attempts remain failed evidence even when later recovery establishes their source result.

`source-control-read.test.mjs` checks the tokenless read protocol, optional absence, callback serialization and refusal of writes or foreign scopes. Its public SDK case resolves the selected package export; `SOFA_TEST_PUBLIC_SDK_ROOT` may point to an isolated packed consumer for prerelease development without changing application dependencies. `SourceControlTests` checks bounded UTF-8 framing, allowed read resources and intended-App/user/repository authority. Browser issue tests distinguish current source questions, eligibility and unavailable application submission. These fixtures do not prove actual connected App-user acceptance. Release verification also publishes outside the checkout and executes the bundled offline validator, catching incomplete runtime SDK packaging.

`web.test.mjs` checks the observation server's fixed repository scope, cache, failure handling and read-only HTTP boundary. `browser/` exercises source links, unavailable and stale observations, keyboard navigation, mobile layout and accessibility in both themes. Run `npx playwright install --with-deps chromium` once before `npm run test:browser`; browser results are written under ignored `test-results/browser/` and `test-reports/` directories, separately from provider evidence under `test-results/identity/` and retained by CI.

`SoFa.Runtime.Tests/` checks admission and fencing against PostgreSQL, kernel peer identity, GitHub authority and receipts, bounded processes, validator diagnostics and container isolation. `bridge.test.mjs` and `engine-cleanup.test.mjs` cover receipt cleanup and engine-session cleanup.

`security/` verifies repository secret-scanner integrity and redaction. Run all checks with `npm run verify` at the root; `npm run test:runtime` provisions an isolated PostgreSQL test container when `SOFA_TEST_DATABASE` is absent. These tests do not replace a live issue-to-stage receipt or owner approval for refinement.

For an isolated .NET container with host-provisioned `SOFA_TEST_DATABASE`, run `npm run verify:container`. It runs the complete application verification, including PostgreSQL and browser tests, and names the excluded Docker engine suite. Run that suite on a trusted Docker host with `npm run test:runtime:host`. Both suites are required for container acceptance; a container pass alone is not full verification. `npm run verify` and CI continue to run every test by default.

`SoFa.Web.Tests/` exercises maintained OIDC/cookie middleware with signed synthetic issuer responses, owner/session deadlines, concurrent provider refresh, source-account callback/permission isolation, per-session observation caches and actual HTTP asset bodies/MIME types. Composition tests prove external mode provisions no provider and development uses only the workspace/provider plus SDK tooling.

`development-identity.test.mjs` checks that setup keeps secrets outside the checkout with private permissions, generates valid certificate chains and refuses replacement of an existing setup. `WorkspaceArchitectureTests` inspects the compiled Workspace assembly's public handler surface and referenced module assemblies. `npm run verify:dotnet` checks Release/format/module activation, compiles a valid semantic handler fixture, independently proves LH1001 and LH1002 fail with their own diagnostics, and runs the compiled architecture tests in the provisioned solution-test lanes.

`npm run verify:identity:host` requires Docker, Chromium, OpenSSL and `certutil`. It builds the exact Release AppHost, provisions an isolated private CA/browser and real pinned Keycloak, then tests development password login without OTP, wrong-password denial, fresh reauthentication, refresh, revocation, outage, accessibility and local cleanup. It takes about twelve minutes because provider revalidation uses the real five-minute interval. Source UI states use explicit browser fixtures; the owner confirmed actual desktop GitHub/operations access and deferred physical-phone rehearsal. Only safe screenshots and summary receipts are retained. Existing `browser/` tests invoke the legacy loopback fixture explicitly so `npm start` remains the authenticated application command.
