# Runtime inventory design

<!-- pdac-scope: cited -->

## Context

The supported .NET Workspace already provides owner/provider admission, independent connected-user GitHub authority, mandatory atomic source request guards, bounded query responses and static JS/CSS. The first #57 slice uses those seams. Canonical architecture is sections 05/07/08 and ADR-0006/0007/0009. No new execution, persistence or deployment choice needs an ADR.

## Goals / Non-Goals

Show verifiable registrations, GitHub runner facts and committed adoption. Do not infer process liveness, physical placement of unmatched GitHub runners, free capacity, scheduling, source reservations or measured cost/tokens/storage. Broader source telemetry is future work through the existing shared SDK. Organization-only registrations are explicitly unsupported in this repository-scoped increment, rather than silently matched to repository-scoped IDs.

## Decisions

### 1. Private allowlisted local observations

Optional `SoFa:Runtime:Registrations` entries contain a bounded public alias and private absolute runner-installation directory; max10. `SoFa:Runtime:Checkouts` entries contain one configured repository and private absolute checkout path; max10, distinct repositories. Configuration is operator-owned, loaded at startup, not browser input. Paths never appear in API output/errors. Empty configuration means unconfigured/incomplete, not no runners/adopters.

A tokenless Node helper under `src/workspace-tools/` receives only the selected local configuration on bounded stdin, through the same clean-environment/process-budget pattern as SourceContract. No secret environment, shell, network, Docker socket, execution engine, npm lifecycle or source scripts. .NET bounds input/output and the process tree lifetime; cancellation kills owned children. Node uses fixed commands/argument arrays and per-command time/output limits. Host refresh requires the current exact-owner session. Add an owner-session lifetime cancellation token, cancelled on removal/expiry/provider revocation. Link the helper budget to that token, RequestAborted and the admitted idle/absolute deadline (deadline expiry must stop a read even without another request). Start the owned helper under the same session lock and current-session check as removal, preventing check-to-start races; recheck before publishing. Kill only this owned process tree on cancellation and drain bounded output. Add logout, expiry and replacement tests while a helper is deliberately blocked; no private read continues or result publishes after session loss. Token cancellation must not dispose a source still reachable by in-flight readers or deadlock request cleanup. Cookie reference rotation of the same valid session preserves its lifetime token. Disconnecting GitHub does not revoke separately authorized host observations; logout/owner-session loss clears all browser data. No local results cached server-side. A singleton nonqueuing host-read semaphore allows at most one helper at a time across all sessions; each helper invokes Git sequentially, so fan-out is at most one Node plus one Git process. Busy returns an explicit retryable busy observation, never empty data. A separate singleton nonqueuing semaphore permits at most two GitHub runtime queries globally. Rejected calls do not start authority/source reads; admitted calls retain the30-second query deadline and release their slot in finally, including cancellation. This is observation request protection, not factory worker scheduling/admission or a capacity signal. Test concurrent requests, bounded child fan-out, busy status and slot release after cancellation. Browser limits itself to these source concurrency bounds and offers explicit retry for busy sources.

Read only fixed `.runner` from each configured directory, no symlink final file, regular file <=32KiB. Accept the producer's UTF-8 BOM; an actual read-only source preflight found BOM-prefixed .runner JSON on both selected installations. Validate bounded positive safe-integer agentId, bounded name and exact HTTPS github.com owner/repository scope; output only alias, repository, ID/name and collection time. Never read `.credentials` or publish the raw file, private directory, server URL or work folder. A registration file is a registration observation, not proof that a process/container is running. Modification time is file metadata, not heartbeat; show both modified/collected times without invented expiry thresholds.

For each checkout, inspect only bounded local Git metadata and read its committed objects through a disposable empty bare repository. Never execute Git against the source checkout or load its configuration as Git runtime configuration. Resolve the selected worktree's fixed .git/HEAD/commondir and loose or packed ref metadata as bounded data, rejecting traversal, malformed/symbolic cycles and unsupported layouts as unknown. Parse only one literal origin URL from the bounded common config (no include expansion or URL rewriting); ambiguous/unsupported syntax is unknown, never a guessed origin. Create an empty bare repository with --template= in a private parent-owned scratch directory; copy only the validated HEAD object ID, not source config. Use GIT_OBJECT_DIRECTORY to read source objects, with clean HOME/XDG, system/global config disabled, replacement objects disabled and protocol.allow=never. The only Git commands are init of owned scratch and cat-file type/size/blob reads of fixed files at the validated commit; no fetch/pull/SSH, credentials, hooks, filters, source aliases or lazy/promisor configuration. Check blob size before reading it. The .NET bridge owns and removes the private scratch directory after normal exit or cancellation. This writes no source checkout/repository file. Verify normalized GitHub HTTPS/SSH origin equals its configured repository. Read only `package.json`, `package-lock.json`, `.lighthouse/sdlc.json` and the fixed installed unattended workflow at that SHA. Output selected Lighthouse CLI declaration, root lockfile resolution, SDLC manifest version and immutable workflow source reference separately (the installed workflow uses a trusted harness checkout repository/ref, not a reusable-workflow call), with source revision/links. Missing files/invalid origin/failure preserve unknown and partial evidence. Bounds: helper stdin128KiB; stdout1MiB; stderr8KiB; whole helper10seconds with a128MiB Node heap; .runner32KiB; .git/HEAD/commondir8KiB each; common config64KiB; loose ref1KiB; packed refs2MiB; each selected committed file and Git stdout2MiB; Git stderr8KiB and each command at most2seconds within the remaining helper budget. Reject at/over-bound anomalies as unavailable/incomplete with source coverage preserved, never empty adoption. Configuration permits at most10 registrations and10 distinct configured checkouts; aliases64characters and private paths4096characters, rejecting control characters. The serialized host and GitHub endpoint responses are each capped at2MiB; projection overflow returns a small unavailable/incomplete response, preserving known source total/time and no zero/complete claim. Test each bound and final serialized response, not only upstream bytes. Reading committed files does not prove installed/deployed versions or a policy deviation. Do not clone/pull/install/upgrade. Configured-source coverage does not establish all repositories using Lighthouse.

Hostile system/global/local Git config tests install credential-helper, fsmonitor, SSH, URL rewrite, include, attributes/filter and template sentinels. Verify none runs or is expanded, the literal origin and exact committed object are preserved, and the source checkout/ref/config remains unchanged. Cover ordinary worktrees, detached HEAD, packed refs and unsupported metadata. No network-capable Git command or source Git configuration is invoked.

Alternative: host Docker socket, process scan or operator `gh` fallback. Rejected: broad authority, credentials and guessed mappings are unnecessary for a registration overview. Direct .NET Git/process parsing is possible; the existing bounded tokenless Node bridge is easier to test using built-in Node and public Git behavior without new dependencies.

### 2. Connected-user GitHub repository runners

A separate query per configured repository uses RepositoryAccess and GitHubAuthorization. Extend authority with `AdministrationRead`: effective user admin AND current installation administration read/write grant AND metadata authority. Do not expose another App's runners or infer permissions from successful issue reads. Missing grant returns denied without calling `/actions/runners`; uncertain authority stays unavailable. Every credentialed call uses the existing mandatory atomic source guard and connection stop token; connection/session/generation are rechecked before response.

Call only fixed `/repos/{configured}/actions/runners?per_page=100&page=1` with existing 2MiB transport bound and query deadline, including authority checks. Return up to100 runners with source total_count, collected count, complete/partial coverage; do not enumerate unbounded pages. Validate identities, bounded names/status/labels and boolean busy. Unknown status remains unknown; missing busy is unknown, never idle. total_count=0 plus a valid empty collection is the only no-runners claim. Unauthorized invalidates the connection; 403/404 clears affected GitHub data as denied; transient failure may preserve original browser data marked stale, never a fresh healthy count. DataScope binds browser GitHub inventory to account generation. No operator token/anonymous fallback.

### 3. Presentation and correlations

One protected `/workspace/runtime` and owner-protected local `/api/runtime/host`, plus connected-user `/api/runtime/{owner}/{repository}`. Public static assets contain no observations. Navigation links from existing workspace views. Explicit refresh only, initial read on navigation; no poller/storage. Fetch local and GitHub facts independently, retaining source times and bounds. DOM text nodes and fixed source URLs only; no raw Markdown/HTML or private paths.

Show local registration and GitHub inventory as separate facts. A registration-to-GitHub match requires identical normalized repository scope AND numeric runner ID; a differing name is a visible conflict, not silently overwritten. Equal IDs from different repositories do not match. This proves matching registration identity only, never process health/placement. Unmatched GitHub runners have unknown physical location; even `self-hosted`/host-like labels cannot locate them. Process health, capacity/usage and leases are explicitly unobserved. Actions/Factory/Issues/settings links supply source recovery without mutations.

GitHub disconnect/replacement/global denial clears GitHub facts immediately; repository denial clears that scope before sibling reads settle. Keep host facts independent of GitHub grants and clear everything on owner401. A partial catalog remains incomplete. Errors preserve original collection times only where explicitly stale; successful empty source does not retain deleted records. No mixed account/pagination join. Desktop keyboard and390px layouts retain accessible headings/statuses/focus.

## Test and Evidence Plan

- Node fixtures: valid/malformed/oversized/symlink registration, organization scope, safe output/redaction; actual temporary committed Git checkout proves remote normalization, exact committed values despite dirty files, absent/oversized configs and no mutation. Same runner ID across different scopes stays separate.
- .NET: table-driven authority matrix covers user admin missing, matching App administration read/write missing, metadata missing, wrong installation/account/repository, changed connected user and all-granted success; every denied case makes zero runner calls, and only the current matching account/installation succeeds. Boundary/overflow tests cover each local/protocol limit and final serialized HTTP response; unavailable/incomplete cannot become empty/complete. Owner logout/expiry/provider removal during a held helper cancels its owned process tree and blocks publication; start/remove race, aggregate host1/GitHub2 limits, rejected reads, cancellation slot release and valid-session cookie rotation; options and owner route boundary; denied administration with zero runner calls; source busy/offline/unknown/empty/partial/malformed/401/403/transport and connection-generation/read-stop behavior through existing transport fixture. Preserve all current assertions.
- Browser: independent local/GitHub views, source-scoped joins/conflict/unknown host, permissions, retained-time stale state, immediate denial/account change clearing while sibling read held, refresh and narrow/keyboard accessibility. Fixture evidence labeled synthetic.
- Actual selected host `.runner` and committed-adoption observations with safe receipt, source revision/times and current real GitHub grant limitation. Do not reset owner credentials or claim acting-user success from operator `gh`. Observe independent runner supervision before/after application observation or stop without manipulating workers. Existing99 native run may supply independence evidence only for its observed interval/outcome.
- Run full `npm run verify`, hosted CI and fresh independent review of every configured Done dimension on final candidate. CI/provider/owner acceptance limitations remain explicit. Deploy only a reviewable reversible development preview; production stays separate.

## Migration / Rollback

Configuration is optional and private; existing setups display unconfigured host evidence. No schema/storage migration, worker hook or permission auto-escalation. Roll back the view/query/helper and optional configuration through the reviewed source path; independent runtime remains untouched. #50/#52 acceptance and integration remain prerequisites for merging this stacked branch.
