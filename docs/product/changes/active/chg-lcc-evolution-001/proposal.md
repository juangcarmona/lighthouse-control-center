## Terminology review

The maintainer requested this correction: “my name shouldn't be there” and “We shouldn't talk about factories.” The correction applies to product roles, descriptions and journeys. It does not remove Git authorship, repository URLs or immutable historical records. The earlier proposed personal-deployment actor is removed rather than retained as a product persona.

| Concept | Recommended product term | Meaning and boundary |
| --- | --- | --- |
| Person using LCC | Operator | Admitted user with explicit project/provider scope; no implied repository ownership or administrative grant |
| Person administering execution resources | Runtime administrator | Separately authorized provider/resource actions |
| Person responsible for repository engineering | Repository engineer or maintainer | Repository-defined authority, independent of application access |
| Managed projects and repositories | Fleet | Independent projects observed through a shared operational view |
| Work to deliver | Mission | Issue-centric objective with history, dependencies and accepted outcome; distinct from an execution attempt |
| Operating application | Control Center | The decided application identity; it observes and enables supported authorized actions |
| Broader maritime setting | Harbor, as optional experience language | Could describe where the fleet is observed and prepared; no new configuration object, deployment tier or security authority is inferred |
| Evidence feeding the next improvement | Feedback loop | Observe outcomes, understand evidence, decide an improvement and follow its delivery; existing Lighthouse lifecycle remains authoritative |

Harbor is a recommendation for imagery, not an accepted product-area name. Bay remains a visual/geographic alternative; Loop Point needs a distinct, useful concept before becoming a label. Captain, admiral and harbor-master roles are not introduced: the operational roles must communicate actual permissions. Infrastructure, runner, workflow, run, attempt, runtime provider and model provider retain their precise engineering names.

Existing non-personal artifact IDs containing old terminology remain compatibility references for accepted citations and other active work. Their titles and prose are rewritten in the overlay. The two retired actor IDs appear only in the removal manifest and analysis of the existing graph, not as target roles or examples. Source paths such as GetFactoryPageHandler and historical branch names still identify the actual inspected implementation; this review performs no code/namespace or source-evidence rewrite.
