# Lighthouse adoption and selected issue history

Open a configured repository and expand **Source coverage**, then **Lighthouse adoption**.
Choose **Read adoption evidence** to read its configured committed checkout through the existing
bounded host helper. This read selects only that repository, sends no runner registrations and
does not request GitHub runner administration. Missing configuration leaves adoption unknown;
ordinary authorized issue reads remain available.

The committed producer's `declaredCli`, `lockedCli`, `sdlcVersion` and `workflowRef` are declarations
or lock resolutions at `revision`, with `collectedAt` kept separately from response observation
time. They are not installation or current-policy receipts. No compatible comparison baseline
is wired in this increment, so no drift verdict or upgrade recommendation is shown. An observed
issue run retains its own revision and attempt; it does not establish installed capability.

Select an issue, expand **Delivery evidence**, then **Lighthouse history**. The history reuses the
displayed conversation page and existing evidence read; it does not crawl issue events or label
history. Source-dated rows sort chronologically. Undated rows remain visible outside the local,
inclusive UTC date filter. A run update time never supplies a queue or wait endpoint. Equal times
do not establish causality. Workflow execution, validated stage results, questions, PR creation,
merge, head checks and reviews remain different facts. Unsupported result formats stay unverified.

Reviews require the existing effective pull-request-read grant, cover only the first 20 per PR,
and do not establish required protected human approval. A source question does not prove its
resolution. Missing histories do not mean zero interventions. No intervention count, denominator,
autonomy percentage or queued/running/human-wait/PR-wait duration is calculated. Successful execution
does not mean accepted delivery.

## Bounds and privacy

Collection uses at most ten source reports and ten explicitly referenced PRs from one displayed
conversation page, under the existing shared twenty-second optional-evidence deadline. Checks
are limited to the first 100 per PR; reviews to the first 20. Artifact inventories must be complete
within 100 entries, with the existing 2 MiB compressed, source-response and final-response bounds.
Expired artifacts are not downloaded. Conversation pages remain explicit (100 comments per page,
at most ten pages); evidence does not silently fetch another conversation page.

The browser retains at most 1,000 history rows and 1 MiB in memory; excess observations are disclosed.
Identical source versions collapse, while changed outcomes and distinct attempts remain separate.
Missing IDs are not guessed. This candidate rejects cross-name history joins; it does not implement
a rename identity receipt. Refresh/navigation can discard earlier observations; this is not durable
history. Account replacement, denied scope or owner loss clears private projections and existing
generation checks discard late responses. No new credential, source write or persistent cache is used.
