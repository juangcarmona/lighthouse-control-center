# Agent and runner telemetry

The optional stack in [`src/telemetry/`](../../src/telemetry/) receives OTLP through an OpenTelemetry Collector, stores Lighthouse SDLC events in Loki, scrapes native Claude Code metrics with Prometheus and provisions a Grafana dashboard. Control Center does not collect the events or take part in runner scheduling.

Set `SoFa:Telemetry:DashboardUrl` to the Grafana HTTPS base URL to show its dashboard link in Control Center Health. Local development may use loopback HTTP. Health displays the link only in an authorized session; the Control Center sends no telemetry credentials or event data to Grafana.

## Run locally

From the repository root, set a private `GRAFANA_ADMIN_PASSWORD`, then start the stack with `docker compose -f src/telemetry/compose.yaml up -d`. Open Grafana at `http://127.0.0.1:3000`; Collector OTLP/HTTP listens at `http://127.0.0.1:4318`, Prometheus at `http://127.0.0.1:9090` and Loki readiness at `http://127.0.0.1:3100/ready`. The example binds host ports to loopback, uses local filesystem volumes and keeps data for 14 days. This single-node setup has no authentication on Loki or Collector and is for local evaluation only; do not expose its ports to a network.

Set Lighthouse's private `otlpEndpoint` to `http://collector:4318/v1/logs` when it shares this Compose network, or use `http://127.0.0.1:4318/v1/logs` from the host. The same Collector accepts metrics at `/v1/metrics`. Store authentication headers in `LIGHTHOUSE_TELEMETRY_OTLP_HEADERS` or the operator's protected runner secret store. Keep credentials out of URLs, workflow output and repository configuration. Runners on another machine require a separately operated authenticated TLS endpoint; do not open this local example directly to them.

For Claude metrics directly, enable telemetry with `CLAUDE_CODE_ENABLE_TELEMETRY=1`, set `OTEL_METRICS_EXPORTER=otlp`, `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE=cumulative`, `OTEL_LOGS_EXPORTER=none`, `OTEL_EXPORTER_OTLP_PROTOCOL=http/json` and `OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318`. Keep prompt, assistant-response and raw API-body logging disabled. Set `OTEL_METRICS_INCLUDE_SESSION_ID=false` and `OTEL_METRICS_INCLUDE_ACCOUNT_UUID=false` to avoid those identifiers; enable `OTEL_METRICS_INCLUDE_REPOSITORY=true` only when repository attribution is wanted. The Collector removes account, email, organization and session identifiers from metric labels before Prometheus stores them. Claude redacts some custom skill names by default. Setting `OTEL_LOG_TOOL_DETAILS=1` allows reported skill names in metrics; token and cost metrics only include those names from Claude Code v2.1.273 or later. Since logs are disabled, prompts and tool contents are not sent. If logs are enabled later, this setting also exposes additional tool details, so keep `OTEL_LOGS_EXPORTER=none` and review the installed Claude Code version's telemetry configuration before enabling it. Do not send prompts, responses, tool logs or raw API bodies to this stack.

To publish Claude measurements through the Lighthouse event contract, run the session with `lighthouse-sdlc telemetry claude run -- claude ...`. The wrapper receives native metrics on loopback and stores metadata-only `claude.usage.observed` and `claude.cost.observed` events in the runner's private telemetry journal. Configure the runner's `LIGHTHOUSE_TELEMETRY_OTLP_ENDPOINT` to the Collector `/v1/logs` endpoint so its normal telemetry exporter delivers those events to Loki. The wrapper disables log and trace exporters, hashes session IDs, and leaves repository attribution opt-in. Claude reports skill names on token and cost metrics only in supported versions when `OTEL_LOG_TOOL_DETAILS=1`; prompt and tool-content logs remain disabled.

The exporter delivers at least once and saves a per-stream checkpoint after a successful response. If it stops between acknowledgement and checkpoint, the next export may replay events. Loki collapses an exact timestamp and line replay, and the dashboard deduplicates native-step token totals by event ID. Raw event exploration may include changed observations; do not use its row count as a usage total.

## Read the dashboard

The **Lighthouse agent usage** dashboard groups input and output tokens for completed native model steps by executed model and workflow stage. It also groups input tokens by source-reported action. Claude metrics arrive either directly in Prometheus or as Lighthouse contract events in Loki; the dashboard keeps the two sources separate. Both paths group by model, and show skill only when Claude reports it. Claude's reported cost is an estimate, not provider billing. The event explorer includes CLI fallback and compaction events; Lighthouse native totals exclude them. When supplied by the producer, event details include repository, issue, workflow run, attempt, runner, action, source, model and observation times. Loki stores these values as log metadata, not index labels.

Coverage depends on the installed Lighthouse version, runner adoption, producer retention and delivery. Missing model, skill, command, billing, event or source correlation stays unknown. Claude's native metrics do not identify the Lighthouse command or workflow by default. Workflow artifacts and telemetry associations are observations; they do not verify a provider bill or accepted delivery.

## Verify and stop

Run `npm run test:e2e:telemetry` to start disposable Loki, Collector, Prometheus and Grafana containers. It replays native Lighthouse step and Claude contract events, checks event and dashboard-total deduplication by ID and model/skill attribution, then sends synthetic Claude metrics and verifies their Prometheus series. It checks the provisioned dashboard API and removes its containers and volumes on completion. Stop an operator stack with `docker compose -f src/telemetry/compose.yaml down`; add `-v` only when intentionally deleting retained local data.
