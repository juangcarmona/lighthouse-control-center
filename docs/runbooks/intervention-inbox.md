# Intervention inbox

Open `/workspace/attention` after signing in and connecting the GitHub account. The view reuses the factory's bounded, authorized issue-page reader and opens the same issue detail as discovery. Collection performs only reads. Load more explicitly extends project coverage; Refresh starts another collection.

Each `needs-info` or `waiting-review` label is its own source context. The same issue may have both. Repeated observations retain one card per context. These labels do not identify an actual question, its start time, a responsible actor or an approval. The card preserves the issue update and successful observation times separately. Current label observations sort before stale or no-longer-observed contexts, then by issue update and stable identity; this is an explanation of ordering, not inferred urgency.

A missing label, incomplete page, unavailable repository or ordinary comment cannot establish a resolved question. Earlier same-scope contexts may remain marked unobserved with their original time. History is in browser memory, bounded to 1 MiB and 1,000 contexts; omitted history and closing the page do not resolve source work. Repository denial, removal or account change discards affected private history. No browser storage or new server-side execution store is introduced.

Choose **Inspect current question** on a current label context. Only that explicit selection queries the released common SDK through #48; the inbox does not fetch every issue's artifacts or infer admission rules. It checks the immutable issue ID and acting connection before showing a verified current/superseded question, source time, observation time, reservation coverage and shared eligibility. An unavailable contract or source remains explicit. The source contract must be installed on the repository default branch; [PR #115](https://github.com/juangcarmona/sofa/pull/115) supplies this prerequisite.

Supported actions reuse the shared issue controls and protected journal. Prepare first, inspect the effect, then confirm. Ordinary comment and Continue remain distinct. Reconcile the same confirmation after uncertainty; only the shared authenticated receipt can establish source admission or question resolution. Submission alone does not resolve a wait. The collected label card remains separate historical/source context. Protected approvals stay at their source. See [Development issue controls](issue-controls.md) for storage, permission and recovery requirements.

The synthetic browser checks cover distinct/repeated contexts, on-demand shared questions, explicit preparation/confirmation/reconciliation, source-only question resolution, removed labels, stale reads, permission loss, late account replacement, safe text, keyboard focus, uniquely named landmarks, accessibility, and 390px / desktop layouts. They do not prove actual connected-user question/continuation acceptance or a physical-phone session. The owner waived the latter rehearsal; full #51 remains open until the shared-control acceptance trace exists.

The inbox reuses the existing authenticated factory query and #48 source-control boundary. Its selected-context interaction is described in the canonical runtime view; it adds no independent executor or admission policy.
