# Inspect project health

Open **Health** in the workspace rail. Every configured repository remains listed, including denied and unavailable sources. Select a repository, then a workflow observation to inspect its purpose, source status/conclusion, exact contributing run, revision, source times and collection limits.

The first signal uses the existing authenticated GitHub observation API. It covers the latest twenty workflow runs, alongside that adapter's first hundred open issue records. It is not a complete delivery audit or a fixed measurement window. Actions and Issues read permission are both required by this existing adapter. Refresh only reads; it does not launch or recover work. A retained failed refresh is stale, never newly observed. Denial removes prior records.

Engineering quality, adoption/autonomy and resource measurements name their missing sources. Existing Runtime inventory is linked separately; it does not establish installed adoption, process health or free capacity. Workflow success is not deployment or accepted delivery. Numeric units are not applicable to categorical verdicts; definition version is not supplied. Deployment applicability remains unknown without its source. No score, threshold, cost estimate or trend is invented. Comparable history belongs to #54.

Browser fixtures are demonstration data, not a connected-user acceptance receipt. Visual/content acceptance and a real connected-source rehearsal remain owner decisions. Screenshots and check receipts accompany the implementation's Actions artifacts.
